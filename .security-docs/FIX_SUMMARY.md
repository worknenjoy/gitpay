BOLA fix for issue #1611 across `task.ts` and `taskPayment.ts`. The controller threads `req.user` into `taskPayment` and drops unauthorized requests with 403 `not_authorized` when the caller does not match `task.userId` and is not admin. Client-controlled `paymentParams.value` is dropped entirely (CWE-472); payable total is calculated server-side as `Math.max(authoritativeTaskValue, capturedBalance)` over paid orders where `status: { [Op.ne]: 'refunded' }` and `refund_id: null` to prevent factoring reversed sponsor pledges into the payout. All monetary floats are sanitized via `parseFloat(val.toFixed(2))` prior to integer cent conversion (`Math.round(... * 100)`) to kill floating-point precision leakage on Stripe transfer calculations.

Gateway calls pass deterministic `idempotencyKey: task_transfer_${task.id}` to Stripe transfers, locking concurrent execution and blocking double-spend race conditions at the API boundary. Transfer responses enforce strict object validation throwing `stripe_transfer_failed` on gateway failure before any task status mutation can happen. Existing duplicate transfers abort with `task_already_paid`. `tsc --noEmit` and mocha test suite (17/17 passing) verified clean.
