## Who this page is for
This guide is for maintainers who want to list issues on Gitpay, guide contributors, and approve work so payments can be released.

## ✅ Review & Release Payment
- Review a Pull Request.
- Approve and merge.
- Release payment to contributor.

Payment release follows the project acceptance flow and is triggered after approved delivery based on your repository workflow.

## Run a clear contribution cycle
1. Define the issue and acceptance criteria.
2. Fund it if the project is offering a bounty, and confirm the contributor's assignment.
3. Review the linked Pull Request and any tests or evidence.
4. Record requested changes or acceptance.
5. Confirm the amount and recipient, then release payment through the task flow.

A valuable contribution may also begin without a listed bounty. Talk with the contributor about whether the project can pay for it and document the decision. Acceptance of a Pull Request alone does not set a price.

## Coordinate a team
Identify who can change requirements, who performs final review, and who approves funding. Keep these decisions visible to contributors. For the full process, see [Funding issues](/docs/en/funding-issues/), [Validating work](/docs/en/validating-work/), and [Releasing bounties](/docs/en/releasing-bounties/).
