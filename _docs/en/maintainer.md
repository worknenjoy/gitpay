As a maintainer you use Gitpay to get issues in your project solved by outside contributors, paid by you or by sponsors.

## The workflow

1. **Import** the issues you want help with. → [Import issues and projects](/docs/en/getting-started-maintainer/)
2. **Fund** them, or invite sponsors to. → [Fund an issue](/docs/en/sponsor/)
3. **Share** them: **Post on GitHub** adds a comment to the GitHub issue linking to the Gitpay page.
4. **Coordinate** contributors through applications and offers. → [Review applications and offers](/docs/en/validating-work/)
5. **Review and merge** the pull request on GitHub as usual.
6. The contributor **submits the solution** and is paid automatically. → [How bounties are paid out](/docs/en/releasing-bounties/)

## Writing issues that get solved

Contributors decide from the issue alone whether to take it. Before funding an issue:

- describe the expected behavior and how you'll test it;
- link the relevant code or files;
- say what's out of scope;
- mention your project's contribution guidelines and code style.

An issue with a clear definition of done gets fewer pull requests you have to reject.

## Your dashboard

With the **Maintainer** role, your dashboard shows the total paid, your projects and organizations, and the open issues with their assignees. Turn the role on in **Profile → User account → Roles**.
