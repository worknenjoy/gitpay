## Introdução

Mantenedores de projetos open source costumam estar em uma posição estranha: você cria infraestrutura real da qual empresas dependem, mas o fluxo de pagamento não é claro.

Alguns mantenedores dependem de doações ou patrocínios. Outros fazem suporte pago, correções prioritárias, auditorias ou ajuda com integração. Em todos os casos, o desafio é o mesmo: você precisa de uma forma simples de solicitar pagamento que não exija montar uma operação completa de faturamento.

Pedidos de pagamento são uma ferramenta prática aqui. Eles permitem anexar uma ação clara de “pague isto” a um trabalho específico.

## O Problema Típico do Fluxo de Trabalho

O fluxo padrão de um mantenedor costuma ser assim:

- Uma empresa pede ajuda (correção de bug, funcionalidade, auditoria, suporte)
- Vocês combinam o escopo
- Você faz o trabalho
- Você envia uma fatura (ou pergunta “como vocês pagam prestadores?”)
- O processo trava

Pontos de atrito:

- **Você não está no sistema de fornecedores deles**
- **Eles precisam de aprovação de compras**
- **Pagamentos internacionais** criam atrito
- **O pedido não tem dono claro** (o engenheiro pede, o financeiro paga)

Se você já tentou **solicitar pagamento do cliente** (uma empresa) como mantenedor, sabe que o problema real é a falta de dono no fluxo.

### Manter um projeto é “serviço”, mesmo quando não parece

Empresas costumam tratar o trabalho do mantenedor como uma compra de serviço:

- “Você pode priorizar essa correção?”
- “Você pode revisar nossa integração?”
- “Você pode nos ajudar a entender o roadmap?”

Se você enquadra seu trabalho como um entregável com um resultado, o pagamento fica mais fácil de aprovar.

## Pedidos de Pagamento (Em Vez de Faturas)

Pedidos de pagamento simplificam a “última milha”.

Em vez de uma fatura em PDF que precisa ser processada, você fornece um link que pode ser encaminhado internamente com o mínimo de explicação.

É, na prática, um **link de pagamento para freelancer** anexado ao trabalho de manutenção do projeto.

### Para que usar pedidos de pagamento

Trabalhos comuns pagos a mantenedores:

- Correções prioritárias de bugs
- Revisões de segurança ou auditorias
- Suporte à integração (“nos ajude a adotar essa biblioteca”)
- Plantões pagos (office hours)
- Contratos de suporte de longo prazo (divididos em ciclos mensais)

Essa também é uma forma limpa de **cobrar clientes online** por suporte, sem construir uma estrutura de vendas/faturamento.

### Como definir o escopo do trabalho pago de mantenedores (para o pagamento não escapar)

Mantenha o escopo enxuto e baseado em resultado:

- Uma issue
- Um release
- Um relatório de auditoria
- Uma sessão de suporte

Depois, anexe o pedido de pagamento a esse resultado. Quanto mais específico o entregável, mais fácil é para a empresa aprovar e para você evitar pedidos intermináveis de “você também pode…”.

### Opcional: defina um nível de suporte simples

Se você faz suporte pago recorrente, defina um nível leve para que as empresas consigam justificar o gasto:

- Tempo de resposta (ex.: 2 dias úteis)
- Escopo (ex.: dúvidas de integração + resolução de problemas)
- Duração (ex.: mensal)

Depois, envie um pedido de pagamento por ciclo. Essa é uma forma prática de tornar o trabalho do mantenedor “comprável” sem construir um processo de vendas completo.

## Pedidos de Pagamento do Gitpay (Um Encaixe Natural)

O Gitpay permite que prestadores de serviço criem pedidos de pagamento e compartilhem um link de pagamento com os clientes.

- Página inicial do Gitpay: https://gitpay.me
- Pedidos de pagamento do Gitpay (pagamentos de serviços): https://gitpay.me/#/use-cases/service-payments

Você pode manter o fluxo direto:

- Defina o trabalho
- Entregue o trabalho
- Compartilhe o link do pedido de pagamento

### Se o processo de compras for rígido

Algumas empresas exigem cadastro de fornecedor. Nesses casos, os pedidos de pagamento ainda ajudam porque criam uma única etapa de “pague isto” assim que o cadastro é concluído. Você também pode perguntar à empresa o que ela precisa desde o início:

- Quem paga prestadores?
- Vocês exigem fatura ou ordem de compra (PO)?
- Qual é o ciclo de pagamento típico de vocês?

Isso reduz surpresas.

## Exemplos de Uso

### 1) Correção prioritária para uma empresa

Entregável: “Correção da issue #123 + release v1.2.3.”

Envie:

- Link para as notas de release
- Eventuais passos de migração
- Link do pedido de pagamento

### 2) Auditoria de segurança

Entregável: “Notas de auditoria + patches recomendados.”

Vincule o pedido de pagamento a um relatório concreto.

### 3) Sessão de suporte paga

Entregável: “Chamada de suporte de 60 minutos + notas.”

Essa é a versão do mantenedor para “**receber pagamento online como freelancer**”: trabalho de conhecimento com uma etapa de pagamento simples.

### 4) Pagamentos no estilo patrocínio

Se uma empresa quer apoiar o projeto, um pedido de pagamento pode funcionar como um pagamento de patrocínio fácil de executar.

### 5) Sessão prioritária de roadmap

Entregável: “Alinhamento de roadmap de 60 minutos + resumo escrito.”

Isso dá às equipes uma forma clara de conseguir o tempo do mantenedor e dá a você uma forma limpa de fechar o ciclo do pagamento.

## Por Que Esse Fluxo É Mais Simples

Pedidos de pagamento ajudam mantenedores porque reduzem o trabalho administrativo e facilitam o pagamento para as empresas:

- **Nenhum software complexo de faturamento** necessário para receber por suporte
- **Fácil de encaminhar** dentro de uma empresa
- **Escopo claro** anexado a cada pedido
- **Bom para pagamentos internacionais**
- **Funciona para entregáveis digitais** como releases, auditorias e suporte

### Checklist de um minuto para pagamentos de empresas

Para facilitar a aprovação do seu contato, inclua:

- O resultado do entregável (“release v1.2.3 com a correção X”)
- Um link para o trabalho (issue/PR/notas de release)
- O valor
- O link do pedido de pagamento

É a diferença entre “por favor, pague um mantenedor” e “por favor, pague por este resultado concreto”.

### Um hábito amigável para mantenedores

Quando você entregar uma correção ou relatório, inclua o link de pagamento na mesma mensagem. Trate o pagamento como parte da entrega, não como uma tarefa separada.

### Uma nota simples para empresas

Se você quiser facilitar para o seu contato, inclua uma frase que ele possa colar no Slack:

> Mantenedor entregou (correção/auditoria/suporte). Por favor, pague usando este link: (link do pedido de pagamento).
