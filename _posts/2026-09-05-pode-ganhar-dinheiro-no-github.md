## Dá para ganhar dinheiro no GitHub?

Sim. Desenvolvedores ganham dinheiro no GitHub de várias formas, de alguns dólares por mês a uma renda em tempo integral, e isso não exige criar o próximo grande framework. Alguns mantenedores ganham com patrocínios recorrentes, outros recebem por Pull Request através de bounties, e muitos usam sua atividade no GitHub para conseguir trabalhos de consultoria.

## 5 formas de ganhar dinheiro no GitHub

- **GitHub Sponsors** — pagamentos recorrentes da comunidade ou de empresas que dependem do seu trabalho
- **Issues pagas / bounties** — um patrocinador define um valor para uma issue, um contribuidor envia um PR, e o pagamento é liberado quando o PR é aceito
- **Consultoria e suporte** — empresas que usam seu projeto pagam por ajuda na configuração, funcionalidades sob medida ou suporte prioritário
- **Manutenção financiada por empresas** — uma empresa que depende do seu repositório financia trabalho contínuo ou patrocina funcionalidades específicas
- **Trabalho freelance originado no GitHub** — suas contribuições públicas funcionam como portfólio e geram trabalho remunerado com clientes

## Por que bounties são a forma mais rápida de começar

Os valores de bounties variam conforme o escopo:

- Correções pequenas e bugs simples: **US$ 20–US$ 200**
- Funcionalidades e integrações: **US$ 200–US$ 2.500**
- Funcionalidades grandes ou mudanças de arquitetura: **US$ 2.500–US$ 25.000**

Diferente do patrocínio, que cresce devagar, uma bounty paga por um trabalho único e bem definido que você pode entregar em uma semana.

## O problema das bounties informais no GitHub

Muitos mantenedores já oferecem "pago por um PR" em um comentário de issue, mas bounties informais têm atrito real:

- Não há garantia de pagamento (escrow), então o contribuidor trabalha na confiança
- Não há processo claro para definir quem recebe se duas pessoas enviarem a correção
- O pagamento depende do mantenedor lembrar de dar retorno
- Pagamentos internacionais somam taxas e atrasos

## Como o Gitpay transforma issues do GitHub em bounties pagas

O Gitpay conecta patrocinadores, mantenedores e contribuidores diretamente sobre o seu fluxo de trabalho no GitHub:

1. Um patrocinador ou mantenedor abre (ou importa) uma issue do GitHub e a financia como uma tarefa
2. Contribuidores navegam pelas tarefas disponíveis e se candidatam para a que combina com eles
3. O contribuidor envia um Pull Request referente à issue
4. Depois que o PR é aceito, o contribuidor solicita o pagamento e recebe

Sem planilhas, sem cobrar pagamento no direct — a bounty, o PR e o pagamento ficam ligados à mesma issue do início ao fim.

## Exemplos de uso

- Um mantenedor financia um backlog de issues "help wanted" para acelerar o desenvolvimento
- Uma empresa patrocina uma funcionalidade que precisa em uma dependência que não mantém
- Um contribuidor constrói histórico (e renda) trabalhando em issues financiadas em vários repositórios
- Um desenvolvedor freelancer usa issues financiadas como trabalho constante e de baixo atrito entre clientes

## Como começar

- **Quer ganhar?** Veja as issues financiadas, candidate-se, envie um PR e solicite o pagamento quando ele for aceito.
- **Quer financiar trabalho?** Transforme uma issue do GitHub em tarefa, defina uma bounty e libere o pagamento quando o PR for entregue.
