## Can you earn money from GitHub?

Yes. Developers earn money from GitHub in several ways, from a few dollars a month to full-time income, and it doesn't require building the next big framework. Some maintainers earn through recurring sponsorships, others get paid per pull request through bounties, and many use their GitHub activity to land consulting work.

## 5 ways developers earn money on GitHub

- **GitHub Sponsors** — recurring payments from the community or companies that depend on your work
- **Paid issues / bounties** — a sponsor attaches a price to an issue, a contributor submits a PR, and payment is released on merge
- **Consulting and support** — companies using your project pay for setup help, custom features, or priority support
- **Company-funded maintenance** — a business that depends on your repository funds ongoing work or sponsors specific features
- **Freelance work sourced from GitHub** — your public contributions act as a portfolio that leads to paid client work

## Why bounties are the fastest way to start

Bounty amounts vary by scope:

- Micro-fixes and small bugs: **$20–$200**
- Feature-level work and integrations: **$200–$2,500**
- Major features or architecture changes: **$2,500–$25,000**

Unlike sponsorships, which build slowly, a bounty pays for a single, well-defined piece of work you can complete this week.

## The problem with informal GitHub bounties

Plenty of maintainers already offer to "pay for a PR" in an issue comment, but informal bounties have real friction:

- No escrow, so contributors work on trust alone
- No clear process for who gets paid if two people submit a fix
- Payment depends on the maintainer remembering to follow up
- Cross-border payments add fees and delays

## How Gitpay turns GitHub issues into paid bounties

Gitpay connects sponsors, maintainers, and contributors directly on top of your existing GitHub workflow:

1. A sponsor or maintainer opens (or imports) a GitHub issue and funds it as a task
2. Contributors browse open tasks and apply to work on the one that fits
3. The contributor submits a Pull Request against the issue
4. Once the PR is merged, the contributor requests payment and gets paid

No spreadsheets, no chasing payments in DMs — the bounty, the PR, and the payout are tied to the same issue from start to finish.

## Example use cases

- A maintainer funds a backlog of "help wanted" issues to speed up development
- A company sponsors a feature it needs in a dependency it doesn't maintain
- A contributor builds a track record (and income) by working through funded issues across multiple repositories
- A freelance developer uses funded issues as steady, low-friction project work between clients
